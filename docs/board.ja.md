# Web ボードと常駐サーバー

agent-adjutant は、複数リポジトリのタスク監視、セッション管理、差分確認、エージェントからの判断待ち（gate）への回答を一画面で行う Web ボードを提供します。

---

## 概要と起動モード

ボードの配信方法には次の2種類があります。

1. **常駐サーバー（`adj server start`）［推奨］**:
   state ディレクトリごとに1つのバックグラウンドプロセスを立ち上げ、全リポジトリのボードを `/b/<slug>/` で配り、`/` で横断ダッシュボードを提供します。
2. **リポジトリ hub の個別ボード（`adjutant serve` または自動起動 `hubServe`）**:
   対象リポジトリの hub MCP サーバーが、その hub の生存期間中に限って直接配信します（既定ポートは 4577、埋まっていれば空きポート）。そのリポジトリのタスクと worker だけを表示します。

### 常駐サーバーの操作コマンド

```bash
adj server start [--port <port>] [--foreground] [--no-open]
adj server status [--json]
adj server stop
adj server restart [--port <port>] [--open]
```

- **ポートの割り当て**: 既定では `127.0.0.1:4577` を使い、埋まっている場合は空いているポートを自動で選びます。
- **リポジトリの切り替え**: 常駐サーバーでは `/` は「いまの仕事」を開きます。左のレールの「ボード」を選ぶと、隣の列に全リポジトリと親タスク hub の一覧が並びます。「すべて」（`/?view=agent`）を選ぶと全ボードのタスクを一括表示できます。
- **自動再接続**: `adj server restart` の実行前後でポートが変わらなければ、ブラウザの各タブは自動で再接続します。
- **セキュリティとトークン**: `127.0.0.1` のループバックアドレスにのみバインドします。すべてのリクエストに `~/.local/state/adjutant/dashboard-token` に保存されたトークンが必要です。ページは開いたときの URL クエリ `token` からトークンを読み取り、`X-Adjutant-Token` ヘッダーに載せて送ります。状態を変更するリクエストは、トークンがこのヘッダーで届かないと拒否されます。これとは別に、状態を変更するリクエストとターミナルの WebSocket 接続では、ブラウザが送る `Origin` ヘッダーがボード自身のオリジンと一致している必要があります。

### launchd による常駐化（macOS）

ログイン時に常駐サーバーを自動起動するには、`~/Library/LaunchAgents/adj.server.plist` を作成します。

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
  <key>Label</key><string>adj.server</string>
  <key>ProgramArguments</key>
  <array>
    <string>/path/to/adj</string>
    <string>server</string>
    <string>start</string>
    <string>--foreground</string>
    <string>--no-open</string>
  </array>
  <key>KeepAlive</key><true/>
  <key>EnvironmentVariables</key>
  <dict>
    <key>PATH</key><string>/usr/local/bin:/opt/homebrew/bin:/usr/bin:/bin</string>
  </dict>
</dict>
</plist>
```

- 登録: `launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/adj.server.plist`
- 停止: `launchctl bootout gui/$(id -u)/adj.server`
- 再起動: `launchctl kickstart -k gui/$(id -u)/adj.server`（`KeepAlive` の配下では `adj server restart` を使わないでください。launchd の自動再起動と競合します）

## 画面構成と主なビュー

ページは、アイコンのレールと、選んだ場所の一覧を出す隣の列でできています。レールには **いまの仕事**、**TODO**、**レビュー**、**ボード** があり、その上に組織の切り替えと＋ボタン（「依頼する」）、下に通知の設定とテーマがあります。いまの仕事・TODO・ボードの一覧の列は、先頭にも「依頼する」ボタンがあります（レビューの一覧にはありません）。使用量（レート制限）は、TODO 以外の一覧の列の最下部に固定されます。行の右端に `#N マージ` が出るのは PR がマージされてからで、それまでの行には Issue や PR の番号は出ません。常駐サーバーでは `/` が「いまの仕事」を開き、`/?view=review` が「レビュー」、`/?view=agent` が「すべて」、ボード自身のアドレス（`/b/<slug>/`）がそのボードを開きます。一覧の列の幅は 240px から 560px の間でドラッグでき、覚えられます。1つだけ配っているボードには、レールとボードだけが出ます。

### 1. いまの仕事（`?view=work`）

全リポジトリの進行中の作業を3列で一括管理するメインビューです。
- **左列**: アクティブなセッション、hub、gate、レビュー依頼の一覧。
- **中央列**: 選択中のセッションまたは hub の内蔵 tmux ターミナル。上には固定の見出しがあり、タイトル、ブランチとエージェント、Issue と PR へのリンク、右端のボタン（タスクの worker は「下読みを見る」か「下読みする」、「タスク詳細」「IDE」「セッションを閉じる」、hub は「hub の詳細」、親タスクの hub はさらに「親タスクの詳細」）が並びます。PR がマージも閉じられもしていないタスクには、下読みがあるとき（またはタスクの下読みの情報が届くまでと、下読みの途中）は「下読みを見る」、PR にまだ下読みがないときは「下読みする」が出ます。worker の見出しは、エージェントの横にセッションの状態を一語で出し、右端の ⋯ メニューにほかの操作（タスクのないセッションなら「タスクにする…」「既存のタスクに紐づける…」、それに「セッションを再起動…」「端末で開く」「パスをコピー」「片付ける…」）をまとめます。ターミナルの上にバーはありません。接続が切れたときだけ、ターミナルを覆う案内に「再接続」が出ます。止まっていて再開できる worker なら、そこに「再開」が出ます。以下はすべてターミナルの上に重ねて出し、ターミナルの場所は取りません。質問が出ても消えても、ターミナルの大きさは変わりません。
  - **質問**はターミナルの上端から降りてきます。定型の確認（`quick`）はその行で答え、それ以外は「開いて答える」の1行で、質問カードを開きます。hub の着手確認（`quick` でない `dispatch` の質問）は、ターミナルの上半分に重なるフォームで、回答ボタンはいつも見えます。たたんで1行にもできます。
  - **マージ済みのセッション**は、待っている質問がないときに、専用の1行が出ます（worker が自分で片付けの質問を開いていれば、その質問だけで聞きます）。失うものがなければ「PR #N マージ済み。片付けてセッションを閉じる？」に、チップ「未コミット 0」「未 push 0」、ボタン「片付ける」「残す」が並びます。失う変更があれば、質問ではなく「マージ済みですが、消えると困る変更があります」という警告に数が付き、「ターミナルで確かめる」だけが出ます。消すボタンはありません。
  - **右下の2つのボタン**。「最後のメッセージ」は、エージェントの最後の発言を Markdown のまま整形して見せます（ボードに全文が残っていれば全文）。「書いて送る」は広い入力欄を開き、書いた文章を1回の貼り付けとしてターミナルに入れます。「送ったら Enter も押す」を選ぶと、そのあとに Enter も押します（⌘Enter か Ctrl+Enter で送信）。下書きは、ページを開いている間はセッションごとに残ります。文章は1回の貼り付けとして入ります。ブラケット貼り付けを読むエージェント（Claude Code など）には1つの入力として届き、読まないプログラムには、1行ずつ打ったように届きます。
  - **何も選んでいないとき**、中央はターミナルの代わりに空の状態になります。`terminal` アイコン、太字の「セッションを選んでください」、「左の一覧から選ぶと、ここにターミナルが出ます。」の1行です。アドレスがセッションを指していないときに出ます。組織にタスクのあるセッションがないときや、選択を外したときです。
  - **hub** はここでは右列がありません。状態と件数は見出しの1行に出し、残り（待ちキュー、受信箱、動いていない worktree、操作）は「hub の詳細」のダイアログで開きます。止まっている hub のターミナルには「hub を起動」が重なります（着手確認があれば、その上に1行で出ます）。起動の依頼を出している間は「起動しています…」と出て、ボタンはありません。
  - **親タスクの詳細**（親タスクの hub の見出しの「親タスクの詳細」）は、タスク詳細と同じ目次つきのダイアログです。目次は 概要（親 Issue へのリンク、マージ済みの数 N / M、子タスクとその状態）/ 離れていた間に / 操作（「次を着手させる」「子タスクを足す」）です。
  - **タスク詳細**（見出しの「タスク詳細」）は、1つのダイアログを開きます。ヘッダーは、リポジトリ・Issue・PR・フェーズの1行、タイトル、そしてタスクが何を待っているか、いま何をしているかの1行です。左の目次（概要 / 変更 / 経過 / 詳細）は1つのスクロールの中を移動し、画面に出ている部分を示します。概要は、依頼 → ゴール → 計画 → 質問と回答（答えた質問ごとに、選んだ内容と「そのときのカード」）→ いま の順です。回答欄はありません。質問に答えるのは、ターミナルの上の質問と TODO です。申し送りは詳細にだけ出ます。
  - **タスクの AI 下読み**（見出しの「下読みを見る」）は、1つのダイアログを開きます。中央はターミナルのままです。ヘッダーは、リポジトリ・PR・「あなたのタスク」の1行、タイトル `AI 下読み — <タスクのタイトル>`、そして読み終えた時刻と件数の1行（「下読みの worker が5分前に読み終えました · 要注意 2 · 確認 3 · 気になる 2」。件数は、記録にあるものだけ出ます）です。読んでいる間は「下読み中です」、まだ読んでいないときは「まだ下読みしていません」と出ます。ヘッダーの右には、下読みがあって PR が生きているときだけ「読み直す」、下読みがあるあいだ「worker に渡す（N）」（N は渡すコメントの数）、読み手が動いている間は「下読みを閉じる」が出ます。下読みは目次のない1つのスクロールです。先頭に、止まっている hub（「hub を起動」）、前の push 時点の下読み（「下読みし直す」）、読み込めなかった情報の帯が出て、そのあとは、レビューの中央と同じグループが同じ順で続きます（下の「レビュー」を参照）。要点、読み手のメモが行に付いた差分、設計判断・テスト・書かれていないこと、この PR について、の順です（前の形式の下読みには、見るポイントと読む順も出ます）。読み手のターミナルはありません。最初の下読みの前は、「まだ下読みしていません」と「下読みする」ボタンが出ます。順番待ちや実行中なら「下読み中です」です。見出しの「下読みする」は、ダイアログを開いたうえで、下読みを頼める状態なら頼みます。頼めないときは、開くだけで、その理由がダイアログに出ます。1ファイルが 1,500 行を超える PR では頼まず、レビューの一覧と同じく、ダイアログで分割案を選べるようにします。コメントは、レビューと同じく差分の行に書きます（下の「レビュー」を参照）。「worker に渡す（N）」は、全体のコメントを書くダイアログを開き、「N 件を worker に渡す」でタスクの worker に渡します。ファイルのないコメントは、そこに「PR 全体へのコメント」として並びます。ダイアログは開いている間、ページの状態に合わせて変わり、ほかの行を選ぶと閉じます。Esc と × で閉じると、見出しのボタンにフォーカスが戻ります。古い `pane=ai` のリンクは、このダイアログを開いた状態でタスクを開きます。
- **右列**: タスク、hub、親タスク、タスクのないセッション、タスクの AI 下読みでは出ません。出るのは、レビュー依頼のパネル（その読み手）と、タスクカードのない確認待ちのパネルです。

#### どのセッションが選ばれるか
- **いまの仕事を開いたとき**（最初の読み込み、`/`、TODO など別のビューからの戻り、Back）に何も選んでいなければ、最後に選んだセッションを選びます。覚えるのはブラウザごと・組織ごとです（`localStorage`、組織ごとに1つのキー `adj.workLast.<オーナー>`）。そのセッションがなくなっているとき、またはリポジトリの絞り込みで隠れているときは、その組織で最初の「タスクのあるセッション」を選び、それもなければ空の状態を出します。たたんだグループの中のセッションでも選びます。アドレスは置き換えるので、Back で空のアドレスには戻りません。行を選んだとき、リンクで開いたときも同じように覚えます。ページが自分で選んだ行（この代わりの選択や、組織の切り替え）は覚えず、選択を外しても覚えたものは消えません。
- **最初のタスクのあるセッション**は、描かれた一覧で最初の、タスクとセッションを持つ行です。マージ済みでも飛ばしません。hub と、動いているものがないタスクは数えません。そうした行がすべてたたんだグループの中にあるときだけ、たたんだグループの中を探します。
- **組織を切り替える**と、その組織で最初の「タスクのあるセッション」を選びます（その組織で覚えている行ではありません）。なければ空の状態を出します。
- **レールの2つの項目**は、それぞれの一覧を持ちます。「レビュー」から「いまの仕事」を押すと、開いていた PR を外して、最後に選んだセッションを選びます。すでに「いまの仕事」にいるときは何もしません。「レビュー」を押すと、最後に見た PR が一覧に残っていればそれを開き、なければ何も選びません。中央に、もう一方の一覧のセッションや PR が残ることはありません。

#### 組織・リポジトリ・階層
左列には、組織（GitHub のオーナー）を1つ選んで、その仕事だけを表示します。
- **組織の切り替え**: レールの最上部のアバターで、その下に組織の名前と ⇕ が出ます。メニューはホバーかキーボードフォーカス（タップでも）で開き、いまの組織に ✓ が付き、登録済みリポジトリのオーナーが並び、それぞれで待っている件数が出ます。アバターのバッジはほかの組織の合計です。組織を選ぶと、その組織で最初の「タスクのあるセッション」が選ばれます。別の組織の行へのリンクを開くと、その組織に切り替わります。
- **リポジトリの絞り込み**: 「すべて」か、その組織のリポジトリを1つ選びます。1つ選ぶとリポジトリの見出しは出ません。
- **階層**: リポジトリ → hub → セッション。hub はグループの先頭の行で、動かしているタスクはその下に字下げして並びます。親 Issue の hub には、親の番号・タイトルと `n / m マージ` の進み具合が出ます。
- **依頼する**: hub にタスクを頼むダイアログを1つ開きます。リポジトリ（その組織のもの）と hub（リポジトリの hub か、親タスクの hub）を選び、やってほしいことを書いて、「渡す」（Ctrl/⌘+Enter）で送るか、「あとで（Backlog）」に置きます。送らなかった文章は次に開くときまで残ります。新規タスクのボタンと「子タスクを足す」も同じダイアログを開きます（ボードを1つだけ立てているときは、これまでのフォームのままです）。
- **未読の依頼**: hub の行に、まだ読まれていない依頼の件数と新しい順の件名が出ます。動いていない hub には「hub を起動」が出ます。
- **片付ける**: PR がマージされた行は、worker が終わったあとも一覧に残ります。行の最後の行に、worktree を消すと失う未コミットのファイルと未 push のコミットの数が出ます（読み取り中は「確認しています…」、git の状態が読めないときはボタンなし）。失うものがないときだけ「片付ける」が出て、1回押すと worktree とブランチを消します。その間に作業が増えていたときは何も消さず、強制で消すための片付けダイアログが開きます。TODO とターミナルの上の行は、同じセッションについて、作業の一覧（work document）が持つ事実（セッションの `uncommitted`、`unpushed`、`cleanupKeptAt`）から聞きます。読めなかった、またはまだ届いていない事実は「失うものがない」とは扱いません。「残す」（`POST /api/sessions/<id>/keep`）はその質問を隠します。選んだことは worker 自身の記録に書かれ、その worktree でセッションをもう一度始めるか、worktree を消すまで続きます。行自身の行は、残したかどうかに関わらず変わりません。

#### 新着
人の対応が必要な項目が集まります。
- 新しく開いた gate（判断待ち）
- 権限確認待ち（`waiting`）や質問待ち（`AskUserQuestion`）で止まっているセッション
- gate を開かずにターンを終えた worker
- 失敗したセッション
- あなたの対応が必要な PR（変更依頼、CI 失敗、承認済み、マージされずにクローズ）

gate に回答する、ターミナルで入力する、または「既読（`done` / `done_all`）」を押すと新着から外れます。

#### 離れていた間に
タスクパネルの先頭に、前回の確認以降に発生した出来事（工程の遷移、gate の発生、権限待ち、ターンの完了など）を時系列で要約表示します。

#### タスクを置く（Parking）
PdM やデザイナーの確認待ち、外部レビュー待ち、マージ待ちなど、一時的に作業を保留したいときに使います。
- CLI: `adj task park --id <id> --reason pdm|design|review|merge-timing|other [--text <text>]`
- CLI: `adj task unpark --id <id>`
- UI: タスクサマリの「置く」ボタンから実行
置いたタスクは新着に入らず、デスクトップ通知も抑制されます。

### 2. レビュー（`?view=review`）

レールの「レビュー」は、ほかの人に頼まれた PR と、同期したリポジトリの PR の一覧を開きます。自分のタスクの PR はここには出ません。タスクの下読みは、そのターミナルの見出しから開きます。アドレス `/?view=review` で一覧が開き、再読み込みしても変わりません。`/?view=review&task=pr:<owner/repo#N>` は1つの PR を開きます（古い版の `?view=work&task=pr:…` のリンクも同じ画面に着きます）。Back と Forward で「いまの仕事」と「レビュー」を行き来すると、それぞれの一覧と中央が元に戻ります。
- **一覧**: 行ごとに、規模（S / M / L）、CI 状態、レビュアーの順番が出ます。自分に頼まれた PR は、タイトル行の先頭に小さな「依頼」が付きます。
- **何も選んでいないとき**、中央は空の状態です。`rate_review` アイコンと、「PR を選んでください」「左の一覧から選ぶと、ここに AI 下読みが出ます。」が出ます。一覧に PR がないときは、「レビューする PR はありません」「レビューを頼まれた PR と、同期したリポジトリの PR がここに出ます。」になります。ただし、そう言うのは同期が最後まで終わったあとだけです。まだ一度も同期していなければ「まだ同期していません」、最後の同期が途中で切れたか失敗していれば「PR が見つかりませんでした」と、出ていない PR があるかもしれないことを出します。一覧を読み込む前は「読み込み中…」、読み込めなかったときはその旨を出します。
- **中央**には、選んだ PR の見出しが固定で出ます。1行目は `#<番号> <タイトル>` で、その下に `<リポジトリ> · @<作者> · +<追加> −<削除> · <n> files · CI <状態>` が出ます。CI は 失敗 N、実行中、通過、なし のどれかです。右端には「GitHub で開く」、「読み直す」（下読みがあり、PR が生きていて、レビュー対象外でないときだけ）、「レビューを送る」（下読みがあり、コメントを読み込んだあと。送るコメントの数がバッジに出ます。PR が生きていないときは押せません）、「拡大」があります。タブはありません。
  - 最初の下読みの前は、中央に「まだ下読みしていません」と「下読みする」ボタンが出ます。下読みを頼めないときは、hub の理由を添えてボタンが無効になり、依頼を出している間は「依頼中…」と出ます。順番待ちや実行中は、代わりに「下読み中です」が出ます（順番待ちなら、その番号も出ます）。
  - 下読みは1つのスクロールで、次の順に並びます。前回のレビューから（レビューのあとに push された PR）、要点（3行でいうと。前の形式の下読みには「前の形式」のカードも）、差分、設計判断・テスト・書かれていないこと、この PR について（PR の事実と下読みした時点。head が動いていれば「下読みし直す」）。前の形式の下読みには、差分の前に見るポイントと読む順も出ます。「前の形式」のカードがそのことを伝え、PR が生きている間は「下読みし直す」を出します。差分はファイルごとに1枚のカードで、読み手の読む順に並びます。ヘッダーにはファイルの種類と「飛ばしてよい」、その下に読み手のメモが出ます。カテゴリのタブも、たたむスイッチもありません。読み手のメモは行の下に出ます。解説（その行が何をしているか）、気になる（質問や修正に値すること）、訳（翻訳したコメント）です。解説には「コメント」、気になるには「コメントにする」があり、どちらにも「聞く」があります。「コメント」は、その行の「＋」と同じく、行の下に空のコメント欄を開きます。「コメントにする」は、作者に宛てた読み手のコメントを入れたコメント欄を開きます（その行に読み手のコメントがすでにあるあいだは出ません）。前回のレビューで自分が書いたコメントは、行の下に「前回のあなたのコメント」として、その後の扱いとともに出ます。古い `pane=diff` や `pane=drafts` のアドレスは、下読みを開きます。
  - 行へのコメント: 行の「＋」で、その行の下にコメント欄（見出しは「あなた」と「未送信」、「やめる」と「コメントを足す」）が開きます。「コメントを足す」を押すまで、何も保存されません。足したコメントには「編集」と「削除」があります。気になるから作ったコメントには「AI の文から」、別の head の差分で書いたコメントには「<sha7> の差分で書きました」と出ます。ファイルへのコメントと、差分に行がなくなったコメントは、ファイルのヘッダーの下に出ます。「レビューを送る」は、全体のコメント（自分で書くまでは読み手の文）、差分に出せないコメント、「N 件を pending review に積む」のあるダイアログを開きます。積んだコメントは GitHub の pending review に一括で入り、送信は GitHub で行います。
  - 巨大な PR: 1ファイルで1,500行を超える変更がある PR には「分割案」ボタンが表示され、レビューしやすい単位への分割案を worker に検討させることができます。
- **右列**は読み手のパネルで、見出しは「読み手 — 読むだけ · コードレビュー hub」です。読み手が動いている間は「下読みを閉じる」も出ます。幅はドラッグで変えられ、覚えられます。
- **「レビュー」を押したとき**は、最後に見た PR が一覧に残っていればそれを開き、なければ何も選びません。

#### コードレビュー hub と読み手
- レビュー hub の起動: `adj hub --review`（または画面上の「hub を起動」）
- 下読みの依頼: `adj review request --pr <URL|owner/repo#N>`（または PR 行のボタン）
- 読み手プロセス: 同時に最大3つの独立した一時ディレクトリで動作し、コードベースを変更せずに差分を読み込みます。

### 3. TODO（`?view=todo`）

全リポジトリで、あなたの番になっているものです。レールの TODO のバッジが件数で、開いていて置かれていない gate と、聞いているマージ済みのセッション（下記）の合計です。レビューを頼まれた PR は入りません。それは「レビュー」にあり、レールの「レビュー」に別の件数があります。ターミナルだけで出る権限確認、置いたタスクの gate、自分のタスクの PR の番は入りません。
- **ポップオーバー**: レールの TODO にポインターを置く（またはキーボードでフォーカスする）と、レールの横に一覧が開きます。定型の確認はその場で答えられ、それ以外の行は、その項目を選んだ状態で TODO を開きます。ポインターとフォーカスが離れるか Escape で閉じ、TODO の画面とダイアログの上では開きません。
- **左**: 「あなたの番」。答えやすい順に並びます。最初が、失うものがないマージ済みのセッション（それぞれ「片付ける」と「残す」。worker が質問を開いているセッションはその質問だけで聞き、失う変更があるものはここに出ず、ターミナルの上の警告になります）、次が定型の確認（古い順）、そのあとが「読んで決める」（着手確認、起票の確認、調査結果と報告、計画、質問、Jules に回す指摘、手で見る確認、diff の順で、同じ種類の中は古い順）です。
- **右**: 選んだ質問を、ダイアログと同じカードで出します（その場で答えられ、diff・Issue の本文・レポートはカードの上に重ねて開きます）。何も待っていなければ「あなたの番はありません」と出ます。

答えた項目はすぐ一覧から消えます。選んでいる項目はページの状態で、アドレスに入るのは `?view=todo` だけです。一覧を絞る場所は `src/ui/todo-view.js` の `todoInScope` の1か所だけです。

### 4. ボード（`?view=agent`）

レールの「ボード」は、一覧の列にボードの一覧、真ん中に選んだボードのカードを出します。

- **ボードの一覧**: 先頭が「すべて」（リポジトリの数つき）で、そのあとにリポジトリが並び、親タスクの hub はそのリポジトリの下に出ます。行には hub の種類（リポジトリ hub か親タスク hub。止まっている hub には「 · 止まっています」がつきます）、状態を表す点（緑が稼働中、灰色が停止中、赤が古い状態）、右端にそのボードでまだ開いているタスクの数が出ます。数は `/api/boards` の `open` で、done と cancelled 以外のタスクをすべて数え、0 のときは出ません。「すべて」はその合計です。どの行にも、その hub をボードの横に開くターミナルのボタンがあります（止まっている hub では、そこに「hub を起動」が出ます）。止まっている hub の行には「起動」もあります。
- **見出し**は1行で、ボードの名前を太字で（「すべて」、リポジトリ名、親タスク hub のボードなら `<リポジトリ> · <hub のキーとタイトル>`）、そのあとに「エージェントの作業」と出ます。
- **6つの列**は同じ幅で、それぞれ名前と件数が出ます。着手前、計画、実装、セルフレビュー、PR・レビュー対応、完了です。着手前はキューが先で（各カードに「キュー N」。N は order）、そのあとに Backlog（「Backlog」）が並び、「次を流す」があります。完了は1日より古いカードを「以前の完了」にたたみます。PR・レビュー対応の列には「PR確認」があり、PR の自動確認が止まっていればそれも出ます。
- **あなたを待っているカード**は、左端が警告色になり、「…を待っています」の1行が出ます。言葉は開いている gate から決まり（着手確認、起票の確認、計画、差分、動作確認、報告、回答、指摘の転送）、gate がなくて PR があなたの番のときは PR から決まります（修正の依頼への対応、マージ、CI の失敗への対応、閉じた PR の判断。どれでもなければ PR のレビュー）。許可待ちで止まっている worker は、エラー色で「許可待ち」と出ます。PR のあるカードには、PR が誰の番かのピルもつきます。
- **ボードの横のターミナル**（常駐サーバー）: 作業中（`dispatched` か `pr`）のタスクか、あなたの番のタスク（gate が開いている、または PR があなたを待っている）のカード、タスクのないセッションのカード、hub の行のターミナルのボタンを押すと、そのターミナルがボードの右のサイドバーに開きます。見出し、ターミナルの上に降りてくる質問、2つの浮かぶボタンは、いまの仕事と同じものです。ボードは左に残ってスクロールでき、列は 140px を下回らず、足りない分は横にスクロールします。サイドバーは右上の × で閉じ、幅は左端のドラッグで変えます（360px から 1400px。矢印キーとダブルクリックも使えます）。幅は覚えられます。アドレスにも残るので（`?task=<id>&pane=term`、または `hub:<id>`、`session:<id>`）、戻る・進むが使えます。Backlog、キュー待ち、完了、取り消しのカードは、代わりに詳細のダイアログが開きます。1つだけ配っているボードにはサイドバーがなく、カードはタスクパネルを開きます。

「人」のボードはなくなりました。あなたを待っているものは TODO にあります。古い `?view=human` のアドレスは、このビューを開きます。

## タスクパネルと Gate

カードをクリックすると、右側に詳細パネルが開きます。

### パネルのタブ構成
1. **タスクサマリ**: Issue / PR リンク、現在の gate、進捗フェーズ、課題、目標、worktree 情報。
2. **ターミナル**: worker セッションの内蔵ターミナル（`terminal.preset: "tmux"` 時）。
3. **コードレビュー**: セルフレビューのラウンド数、指摘事項、差分、検証記録。
4. **動作確認**: 検証コマンド、手動確認チェックリスト、実行結果。
5. **経過**: 過去の gate、回答、工程遷移の履歴。

### Gate（判断待ち）の仕組み

gate は、エージェントが作業を止め、人間の判断を仰ぐためのチェックポイントです。
- **3つの情報構成**: 何を見るべきか、何が決定済みか、エージェントが迷っている点はどこか。待つ gate は必ず答えてほしい問い（`focus`）を持ち、`adj gate open` は `focus` のない gate を受け付けません。
- **gate が運ぶもの**: `steps`（計画の手順。`plan` では必須）、`sections`（調べたことや計画を、エージェントが付けた見出しごとのブロックにしたもの。`found` か `plan` の段階）、`quick`（読むものがなく、1回の操作で答える定型の確認）。
- **主な gate の種類**:
  - `plan`: 実装計画、課題、目標の承認。
  - `diff`: コードレビュー結果と指摘事項の確認。
  - `verify`: 検証コマンドの成否と手動確認事項。
  - `dispatch`: worker 起動前のタスク仕様確認。
  - `result`: 調査結果の報告。承認ではなく読むもので、答えは「分かった」「続けて聞く」「これをタスクにする」の3つ。
- **回答方法**: 選択肢（承認、修正など）のクリック、コメント入力、またはセッションのターミナルで直接入力して解決（`adj gate close --terminal`）。
- **質問カード**（「いまの仕事」でタスクのターミナルの上の行から開きます。ボードのタスクパネルのタブと「拡大」は、これまでの回答欄のままです）: 上から順に読む1つのダイアログです。あなたの依頼（あなたの言葉での依頼とゴール）、調べたこと、計画（diff と verify の gate では「計画とやったこと」。手順と済の印、見てほしいところ、残っている指摘と見送った指摘、懸念点）、前に決まっていること（この質問に関わるときだけ）、そのあとに見出しとしての質問、1行1案の選択肢（推しは太い枠と「推し」の印。カードの中にボタンはありません）、コメント欄、ボタンが並びます。ボタンは選択肢ごとに1つで、選択肢の名前が付きます（16 文字を超える名前は「A で進める」のように先頭の記号で呼びます）。推しが先頭で塗られ、そのあとに差し戻しのボタンが1つ（「計画を直してほしい」「直してほしい」「もう少し調べて」。差し戻すときはコメントが要ります）。選択肢のない gate は種類ごとのボタン（「この計画で進める」「PR にする」「確認した」「着手する」）になります。見送るボタンは無く、やめる案は worker が選択肢の1つとして書きます。右端にリンク、「ターミナルで話す」、⋯ があり、⋯ の中に「解決済みとして閉じる」があります。調べるだけの調査結果は「調査結果」の見出しで結論を太字で先に出し、hub の着手確認は「あなたの依頼」「hub の読み取り」（表）、質問、「着手する」「直す」と右端の「やめる」の順です。中身のない部分は描かず、質問は1回しか書きません。ヘッダーと回答欄は動かず、真ん中だけがスクロールします。diff の gate で、タスクの PR に今の head の下読みがあるときは、見てほしいところの差分の行の下に、読み手のメモ（解説・気になる・訳）がボタンなしで出ます。カードから出るリンクは、カードに無いものだけです。diff の gate の「差分を全部見る」、「Issue の本文」、「レポートを開く」です。
- **ダイアログは重なります**: カードから開くもの（差分の全文、Issue の本文、レポート）はカードの上に重なります。「←」か Esc で1つ戻り、× で全部閉じます。コメント欄に書いたものは、ページを開いている間は残ります。
- **手順やセクションができる前に書かれた gate** も、同じ4つの部分で並びます。依頼はタスクの本文（なければ Issue のタイトルで、本文は1つ奥の層）、調べたことは gate の `problem` と、調査報告では `body`、`steps` のない計画は `decided` を計画として出し、`focus` のない gate は種類ごとの決まった問い（なければタイトル）を聞きます。
- **サーバー稼働確認**: `adj gate open` はボードサーバーが動いているかを判定します（`server: up` / `server: down`）。サーバーが停止している場合は、エージェント自身のターミナルで直接質問するフォールバックを行います。

## カードの自動配置と GitHub 同期

ボードの列は、worker の進捗フェーズと GitHub PR の状態に応じて自動的に移動します。

| PR の状態 | 誰の番か | カードの配置列 |
| --- | --- | --- |
| 下書き（Draft） | worker | 進行中（エージェント） |
| オープン・他者のレビュー待ち | 他のレビュアー | エージェント列（レビュー待ち（他の人）） |
| review bot や CI の完了待ち | bot / CI | エージェント列（bot・CI 待ち） |
| 変更依頼（Changes requested） | あなた | PR・レビュー対応の列（「修正の依頼あり」のピルつき） |
| 承認済み（Approved） | あなた（マージ担当） | PR・レビュー対応の列（「マージ待ち」のピルつき） |
| CI 失敗 | あなた | PR・レビュー対応の列（「CI 失敗」のピルつき） |
| マージ完了 | なし | 完了（Done） |
| マージされずにクローズ | あなた（判断待ち） | PR・レビュー対応の列（「閉じられた」のピルつき） |

常駐サーバーは GitHub の通知イベント（`GET /notifications`）をポーリングし、更新のあった PR を GraphQL で一括取得します。通知が届かない操作もあるため、5分ごとの定期再確認も行われます。手動更新は `adjutant task refresh` または「PR確認」ボタンから実行できます。更新では完了済みのタスクに残っている PR の状態も正し、カードを完了へ移すときも PR を一度読みます。

## セッションの管理

### タスクなしのセッション
事前に Issue やタスクを作らず、一時的な作業用の worker セッションを立ち上げることができます。
- UI: hub パネルの「タスクなしのセッションを始める…」
- API: `POST /api/sessions`（`instruction`, `worktreeName` などを指定）
- 後から `POST /api/sessions/<id>/link` で既存または新規のタスクに紐付け可能です。

### セッションの操作
ターミナル上部のバーまたは API から以下の操作が可能です。
- **再開（`POST /api/sessions/<id>/resume`）**: 停止した worker を既存の worktree で開き直します。
- **再起動（`POST /api/sessions/<id>/restart`）**: 会話履歴を保持したまま、worker のウィンドウを安全に再起動します（新しいバージョンを反映させたい場合などに利用）。
- **外部端末で開く（`POST /api/sessions/<id>/open`）**: 現在のセッションを手元のターミナル（iTerm2 の `tmux -CC attach` など）で直接開きます。
- **片付ける（`POST /api/sessions/<id>/cleanup`）**: 変更がすべてコミット・push されていれば、worktree とローカルブランチを削除して片付けます。未コミットの変更がある場合は確認（ディレクトリ名の再入力）を要求します。
- **残す（`POST /api/sessions/<id>/keep`）**: マージ済みのセッションに、片付けるかを聞くのをやめます。worker の記録に `cleanupKeptAt` を書き、`{"kept": true}` を返します。不明なセッションは 404、hub は 400、記録を書けないときは 500 です。その worktree で worker をもう一度始めると、この印はなくなります。
- **プロンプトへの回答（`POST /api/sessions/<id>/prompt`）**: セッションのターミナル上で待機している権限確認や番号付き選択肢に、指定した数字キー（`1`〜`9`）を送信して回答します。ボディ: `{"id": "<fingerprint>", "key": "<digit>"}`。
  - 送信成功時は `200 {"sent": true}` を返します。
  - 画面上の質問が既に変化・消失（ターミナルで回答済み、タイムアウト等）している場合は `409 {"error": "the question is no longer on screen"}` を返し、キーは送信されません。
  - 選択肢にないキー、読み取りが不確実な場合、tmux で動いていない場合は `400` を返します。
  - セッションが見つからない場合は `404` を返します。

### ターミナル質問（権限確認・選択肢リスト）
エージェント（Claude Code または `agy`）が gate を開かずにターミナル内で尋ねる質問（ツールの実行許可確認や、番号付き選択肢リスト）が発生したとき：
- ボードはセッションの画面キャッシュからプロンプトを検知し、TODO リストの先頭（1タップで完了できる行）およびアクティブなセッションのターミナル上部オーバーレイに表示します。
- gate が開いているセッションでは gate が優先され、ターミナル質問は表示されません。
- ボードのボタンからワンタップで回答キーを送信できます（Enter キーの入力は不要です）：
  - **権限確認**: 選択肢1（`Yes`...）は「許可」（プライマリボタン）、最初の `always allow` / `don't ask again` / `allow all` を含む選択肢は「今後は聞かない」、最後の選択肢（`No`...）は「断る」ボタンになります。
  - **選択肢リスト**: 各選択肢のラベルを最大24文字に切り詰めてボタン表示します。
  - 選択肢の読み取りが不確実な場合（数字飛び、チェックボックスによる複数選択、自由記述入力が必要な場合など）はキー送信ボタンを出さず、「ターミナルで答える」ボタンを1つ表示します。
- サーバーは tmux へのキー送信直前に画面指紋（`id`）を再検証します。質問が既に終了・遷移していた場合は 409 Conflict で拒否し、誤ったキー送信を防ぎます。
